# Логика работы с очередями команд
## 1. Сервер добавляет команды в клиентские очереди
Команды добавляются методом ListRightPushAsync в основные клиентские очереди с префиксом client:commands
>Идемпотентность: Если отправить в очередь две одинаковые команды, то механизм применения конфигураций не сломается 

## 2. Клиент получает необработанные команды из своих очередей
Если в очереди client:processing есть сообщение, то считать его из очереди без удаления
Иначе:
Получить и переместить одну команду в обрабатываемые методом ListRightPopLeftPushAsync из client:commands в client:processing
>Идемпотентность: Клиент должен получать одну и ту же команду до тех пор, пока он ее не обработает или не отменит
> При последовательных запросах клиент будет получать команды либо из очереди processing либо новые команды из очереди commands
> В случае падения связи с редисом при выполнении метода ListRightPopLeftPushAsync логика остается прежней
> Если клиент будет слать параллельные запросы, то порядок команд может быть нарушен, поскольку в processing-очередь может попасть более одной команды

## 3. Подтверждение обработки команды (удаление команды)
Найти команду в списке processing и удалить ее
Нужно ли писать в БД отмененные команды или что с ними делать?
>Идемпотентность: Клиент удаляет команду по ключу. Повторное удаление не ломает механизм, но может выдать исключение или метод просто вернет 0
> В идеале у нас всегда будет 1 элемент в этой очереди
